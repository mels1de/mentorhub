# Roadmap

Claude Code: work on the first unchecked item; tick boxes at session end.

Each phase is a set of feature branches merged into `main` through PRs. Items are tiered
so the thesis is safe even if time runs short:

- **T1 — must** for the defense (the approved topic: API + DB + Docker + Vue integration)
- **T2 — should**: makes it a strong, production-like system
- **T3 — showcase**: portfolio extras; can be described as "future work" in the thesis

Claude writes the code. `🧭` = **decision point / deep dive**: before coding, Claude lays out
the options with trade-offs, Artemii decides, and afterwards Claude walks through the
result in depth (this is the material most likely to come up at the defense).

## Phase 1 — Identity & access (T1) · `feat/auth-*`

- [ ] 🧭 `users` model: email (citext, unique), hashed password (argon2 via `pwdlib`),
      role (`mentee` / `mentor` / `admin`), is_active, is_email_verified
- [ ] 🧭 Register / login / logout; access JWT (15 min) + refresh token (7 days) in an
      httpOnly cookie, **rotated** on every refresh, stored in Redis (revocation = delete)
- [ ] 🧭 `get_current_user` + `require_roles(...)` dependencies (RBAC)
- [ ] Email verification + password reset (signed one-time tokens, emails via Celery →
      Mailpit locally)
- [ ] 🧭 2FA by email OTP: 6 digits, hashed in Redis with 10 min TTL, max 5 attempts,
      then 15 min lockout
- [ ] Rate limiting (Redis fixed-window or sliding-window) on auth endpoints
- [ ] Frontend: auth store, axios interceptor (401 → refresh → retry once, queue
      parallel requests), route guards by role, login/register/2FA forms (VeeValidate + Zod)
- [ ] Inactivity logout: `useInactivityTimer` (mouse/keyboard/scroll/visibility), warning
      modal 2 min before, sync between tabs with `BroadcastChannel`
- [ ] Tests: every auth flow incl. expired/reused refresh token (reuse ⇒ revoke family)

## Phase 4 — Third-party services (T2) · `feat/captcha`, `feat/geo`, `feat/leads`

- [ ] reCAPTCHA v3 (score + action check) on register, login, lead form, behind the
      `CaptchaVerifier` port (Cloudflare Turnstile as a drop-in alternative)
- **Map-based mentor search (Google Maps + PostGIS)** — extends the Phase 2 catalog search,
  same endpoint, same filters; location is just one more filter dimension
  - [ ] 🧭 Location data: `mentor_profiles.location geography(Point, 4326)` + GiST index,
        nullable (online-only mentors), `city` / `country` label, `place_id`; **privacy**:
        exact point stored, public API returns an approximated point (decide: rounding vs
        random offset vs city centroid); migration via GeoAlchemy2
  - [ ] Mentor sets the address with Places Autocomplete in the profile form; backend
        resolves/validates coordinates behind a `Geocoder` port (fake in tests)
  - [ ] Search params on the catalog endpoint, combinable with skills / price / rating:
        - radius: `lat`, `lng`, `radius_km` (capped) → `ST_DWithin` (uses the GiST index)
        - visible area: `bbox=min_lng,min_lat,max_lng,max_lat` → `&&` with
          `ST_MakeEnvelope(...)::geography` (validate, reject antimeridian-crossing or
          split it)
        - `sort=distance` (needs a centre point) → KNN `<->` ordering, `distance_km` in
          the response; offset pagination as for the rest of the catalog
  - [ ] 🧭 Markers vs list: the paginated list is not enough for markers in the viewport.
        Decide: lightweight `/mentors/map-points` (id + approx point, hard cap) with
        client-side clustering vs server-side clustering (`ST_SnapToGrid` /
        `ST_ClusterDBSCAN` per zoom level); cache key per rounded bbox + filters
  - [ ] Frontend `features/mentor-map`: Maps JS API loader, map + list side by side,
        Places Autocomplete search box → map pans/zooms to the place → nearby mentors load;
        **"Search this area"** button after the user moves the map (no request on every pan);
        **"Near me"** via `navigator.geolocation` (permission denied / timeout handled,
        fallback to autocomplete); marker clustering (`@googlemaps/markerclusterer`);
        click on marker → mentor card (photo, skills, price, rating, distance, "Book");
        map state (centre, zoom, bbox, filters) in the URL query like the other filters
  - [ ] Google Maps Platform setup: separate keys for browser (HTTP-referrer restricted,
        Maps JS + Places only) and backend (API-restricted Geocoding), daily quotas +
        billing alerts; verify current Places API (new `PlaceAutocompleteElement` vs
        legacy `Autocomplete`) and Advanced Markers / Map ID requirements before coding
  - [ ] Tests: PostGIS integration tests for radius / bbox / distance sort combined with
        other filters and pagination; invalid bbox / radius → 422; Vitest for the map
        store/URL sync with Google Maps mocked (no real API calls in tests)
- [ ] Lead capture forms (no account needed): UTM source, consent checkbox (GDPR),
      admin list + CSV export, automatic follow-up email sequence via Celery
